01 · The problem

Tenure files depend on independent letters, and independence is still checked by hand

A tenure case needs letters from external reviewers with no close tie to the candidate: no recent co-authorship, no shared department, no advisor relationship. Departments propose 10–20 names per case. Today the chair checks each one by hand, across CVs, Google Scholar and publication lists, and relies on the candidate to disclose ties.

The issue isn't intent. A high-stakes integrity check rests on memory, self-disclosure and manual search. When a conflicted letter is found late, the file stalls or goes back.

02 · Why this problem

I scored five faculty-workflow problems; this one won on evidence, value and fit

OpportunityScore /25

Dossier completeness check16

Scored on pain, frequency, fit with existing research-data assets, and feasibility. I ruled out AI dossier summaries on purpose: an AI judging a career decision is a fairness risk that's hard to detect or contest. This product checks relationships, which can be proven, not the quality of anyone's work.

04 · What the data said

Four data tests: the data finds every shared paper, but a name alone can't find the person

Known shared papers found (recall)Right person from name + institution alone
  • Shared papers: 100% in runs 2–4. Open publication data reliably finds work two people wrote together.
  • Identity stalled at 86–90%. A different researcher with the same name as a real co-author was flagged as a Conflict, the error that destroys a chair's trust.
  • With an ORCID supplied, every test passed. The data was fine; acting on an unconfirmed match was the failure.

Test pairs were public researchers, anchored by ORCID iDs and frozen before each run; pass rules were fixed before results were seen. Only aggregate results are shown.

Every decoy came back as a Conflict. The merge logic used the very relationship it was testing as evidence.
3
Run 4: fixed the logic, still failed (86%)
This was the last tuning round I'd committed to before starting.
4
Stop tuning. Re-scope.
No rule runs on an unconfirmed person. In a simulation every miss ended safely as Insufficient data, with no false Conflicts and no false all-clears.

I set the pass rules before each run, so I didn't argue the misses away. After four rounds the pattern was clear: more tuning wouldn't fix identity, and a person confirming it would.

The trade-off, stated plainly: about two in three names need a chair's click (64% in simulation). That step is now the riskiest assumption, and it can only be tested with real chairs.

06 · What the chair sees

Every reviewer resolves to one of four results, each with its evidence

Conflict
Co-author in the last 5 years, same current university, or a declared advisor.
Chair excludes, or approves with a written reason.
Potential
Older co-authorship, shared past university, a 50+ author paper, or the same name on a shared paper.
Chair reviews the evidence and decides.
No conflict found
No evidence in public data.
Shown with: "This is not proof of independence."
Insufficient data
Identity not confirmed, the record is too thin, or the candidate rarely co-authors.
Chair checks by hand. Never shown as clear.

If a data lookup fails, the row says "Couldn't check" with a retry, never an all-clear. The tool flags; the chair decides; nothing is excluded automatically.

07 · Scope

v1 is the smallest thing a chair could trust

In v1

  • Enter reviewers, or paste a list
  • Confirm each reviewer's identity
  • Check co-authorship and shared universities
  • Candidate declarations (advisors, close ties)
  • One result per name, with evidence
  • Pilot: chair decisions with reasons, audit export

Not in v1, and why

  • Recommending reviewers: earn trust in checking first
  • AI judging dossiers or letters: fairness risk
  • Automatic exclusion: a person decides
  • Per-university rules: one sensible default first
08 · Where it stands

What's proven, what isn't, and what's next

Validated

Not yet tested
